Sign in

One operator account, configured on the server. This console creates events, edits them, and reads who has registered.

There is no password reset and no second account — the credentials come from the server’s environment. If you are locked out, whoever runs the deployment re-runs npm run admin:hash and restarts it.

Every route under /admin/api is answering 503. The surface is switched off rather than left open, so there is nothing to sign in to.

New event

An event is a row in the database and a number on the ledger. Pick the number carefully: everything else here can be edited later.

1 Create POST /admin/api/events
Event id = NFTokenTaxon
— permanent

This integer is the NFTokenTaxon stamped into every badge minted for this event. It is written by NFTokenMint into the token itself and cannot be changed afterwards — not by editing this row, not by anything.

Do not reuse a number. Two events sharing a taxon become one on-chain collection: nfts_by_issuer?taxon=N returns both events’ badges mixed together, and verification cannot tell them apart. The server refuses a duplicate with a 409 for exactly this reason.

Any whole number from 0 to 2147483647. Pick one you can read out loud — it appears in the public URL and in every roster query.

The date of the event itself. The ledger never sees it.

Event-wide fallback badge artwork, used when per-attendee art is unavailable. Editable only until the first badge is minted — NFTokenMint.URI is written into the token and is immutable, so changing it later would leave minted badges pointing at the old artwork.

No seed, secret or private key is ever requested by, displayed in, or stored by this page. Your password is sent once to POST /admin/api/login and is never stored, echoed or logged — not by this page, and not by the server, which holds only a scrypt hash.

A draft event is invisible to the public. Its registration page 404s and it is absent from every public list, deliberately indistinguishable from an id that never existed. Set it to open when you want people to be able to register.

Attendance is an event, not a state. A badge that is later burned still verifies, because the attendee’s NFTokenAcceptOffer hash is the attendance record. That is why the burned count sits next to the minted count rather than being subtracted from it.
